# 반응속도 테스트 명세

메인의 `연습·미니게임` 카드나 도구 페이지 공통 메뉴에서 `#/reaction-test`로 진입한다. 측정 영역 전체가 시작·응답·다음 시도 버튼이다. 마우스·터치·펜 또는 영역에 포커스를 둔 상태의 Enter·Space로 조작할 수 있다.

측정 영역과 결과 화면은 같은 본문 폭과 컨테이너 높이를 공유한다. 일반 데스크톱에서는 뷰포트 높이의 65%를 기준으로 440~680px로 제한한다. 모바일과 짧은 가로형 화면에서는 최소 높이를 낮추고, 공간이 부족하면 헤더와 푸터 사이에 들어가는 크기로 줄인다. 짧은 가로형 화면의 결과는 두 열로 유지하며, 내용이 다 들어가지 않을 때는 잘리는 대신 스크롤할 수 있다. 전체 화면 모드나 JavaScript 크기 측정은 사용하지 않는다.

## 진행과 기록

- 각 시도마다 1,500~5,000ms 사이에서 새 대기 시간을 뽑는다. 빨간 화면이 초록으로 바뀐 뒤 첫 입력을 기록한다. 너무 이른 입력은 성공 횟수에 포함하지 않고 별도로 집계한다.
- 결과 또는 조기 입력 직후 같은 곳을 빠르게 다시 누르면 한 번의 연속 입력으로 취급한다. 다른 위치에서는 즉시 다시 시도할 수 있다.
- 탭 숨김, 창 포커스 이탈, 타임스탬프 이상 또는 큰 렌더링 지연으로 중단된 시도는 집계하지 않는다. 이미 유효하게 기록한 시도는 유지한다. 도구를 벗어나면 현재 세션을 종료한다.
- 단일 입력 방식으로 완료한 세션만 해당 방식의 최고 평균을 갱신할 수 있다. 마우스·터치·펜·키보드 기록은 로컬에 따로 저장한다.
- 유효한 응답 5회 후 진행 표시 대신 평균, 최고 기록과 조기 클릭 횟수, 제목 없는 시도별 기록 5개, 다시 시작 버튼을 표시한다. 중앙값·최단·최장은 계속 계산하지만 별도 통계로 표시하지 않는다.
- 최단 기록의 기존 강조는 유지한다. 최장 기록과 같은 모든 시도의 숫자만 코랄색으로 강조한다(다크 모드 `#E5A1A6`, 라이트 모드에서는 대비를 위해 기존 적색 사용). 반올림 전 값이 모두 같으면 최장 강조를 적용하지 않는다.
- 평균 아래에 `내 최고 기록 · 201 ms`와 `조기 클릭 0회`를 한 줄로 가운데 정렬한다. 입력 방식 이름은 표시하지 않으며, 더 빠른 평균이나 해당 방식의 첫 기록이면 최고 기록 대신 `최고 기록 갱신!`을 표시한다.

## 측정 방식과 한계

- 대기 타이머가 끝나면 첫 `requestAnimationFrame()`에서 DOM의 자극 상태를 전환하고 직후의 `performance.now()`를 시작점으로 잡는다. 자극과 입력 경로에는 React 렌더링이나 CSS 애니메이션이 없다.
- 네이티브 `pointerdown`(키보드는 `keydown`)의 호환되는 `timeStamp`에서 시작점을 뺀다. 처리 시각으로 대신 기록하지 않는다. 화면에 표시할 때만 정수 ms로 반올림한다.
- 예정 시각 대비 자극 프레임이 150ms 초과 지연되거나, 자극 전환 후 첫 후속 프레임이 120ms를 넘기면 해당 시도를 무효화한다. 정상적으로 자극을 표시한 뒤의 느린 응답은 제외하지 않는다.
- 플레이에 서버가 필요하지 않고 측정 경로에서 저장소에 접근하지 않는다. 개인 최고 기록은 세션 종료 후에만 저장하며, 반응속도 테스트 경로에서는 사이트의 Google Analytics 전송을 비활성화한다.
- DOM 변경 시각은 실제 화면에 빛이 나온 시각이 아니다. 브라우저 타이머 정밀도, 화면 주사율, 운영체제와 입력 장치가 결과에 영향을 준다. 수치는 같은 장치와 브라우저에서 비교하는 데 적합하며 물리적 지연을 보정하지 않는다. [Event.timeStamp](https://developer.mozilla.org/en-US/docs/Web/API/Event/timeStamp) · [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)

## 검증

- `npm test`: 통제된 시각 기반의 계산, 조기·연속 입력, 지연된 이벤트 처리, 포커스·렌더링 중단, 통계와 콜백 정리를 확인한다.
- 빌드 미리보기에서 Chrome의 마우스·키보드·터치 에뮬레이션, 오프라인, 모션 줄이기, 6배 CPU 저속화, 모의 포커스·탭 숨김 이벤트와 이동 시 리스너 정리를 확인했다. Firefox와 WebKit에서도 마우스 타임스탬프를 확인했다.
- Chrome 추적의 측정 경로에서 강제 레이아웃은 없었다. 의도적으로 입력 처리를 100ms 늦춰도 점수에 지연이 더해지지 않았고, 자극 직후 약 200ms 멈춘 시도는 무효 처리됐다. 실제 터치 기기와 외부 장비를 이용한 물리 지연은 검증하지 않았다.
