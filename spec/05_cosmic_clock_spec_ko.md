# 우주의 시계

홈의 `힐링` 카드로 `#/cosmic-clock`에 들어간다. 빛의 거리 아래에는 방금 지난 지점과 다음 지점을 표시한다. 각 이름 위에는 해당 유형의 SVG 심볼을 가운데 정렬한다. 가는 선은 두 심볼의 바깥 윤곽을 잇고, 빛 입자는 심볼 중심 사이를 이동한다. 카운트다운은 오른쪽의 다음 지점까지의 시간이다. 마지막 지점에 이르면 입자는 마지막 구간의 오른쪽 심볼 중심에 머물고 카운트다운은 숨긴다. 네 천체의 거리는 가운데 제목 `이동 거리` 아래에 네 행으로 표시한다. 하단에는 확인이 필요한 `초기화` 버튼을 둔다. 펭귄 관찰소는 로컬 개발 시안이며 배포에 포함하지 않는다.

## 시각 저장과 화면 갱신

- `50091.cosmic.departure.v1`에 출발 시각의 Unix 밀리초를 십진 문자열로만 저장한다. 표시값은 저장하지 않는다. 정상 시각은 현재보다 미래여도 초기화 확인 없이는 덮어쓰지 않는다. 값이 없거나 손상되었으면 최초 진입 시각을 저장한다. 저장이 막히면 현재 탭의 메모리에 유지하고 저장할 수 없음을 알린다. 브라우저·기기·출처 간 동기화는 없다.
- `clock.ts`는 출발 시각과 현재 기기 시각의 차이를 기준으로, 열린 탭에서는 `performance.now()`를 사용한다. 기기 시계가 2초 이상 어긋나거나 탭에 돌아오면 다시 동기화한다. 열린 화면에서는 뒤로 가지 않고 잠시 멈추며, 새로고침 뒤에는 보정된 기기 시각으로 다시 계산하므로 표시가 더 작아질 수 있다. 저장 시각이 미래인 새 세션에서는 0부터 기다린다.
- 경과 시간은 1초 단위로 표시하며 물리적 길이인 24시간과 율리우스년(365.25일)을 사용한다. 몇 번째 달력 날짜인지 계산하지 않으며 앞쪽의 0 단위는 생략한다. 같은 자릿수에서 숫자만 바뀔 때 각 시간 단위의 위치를 유지한다. 거리는 기본 km, `10^15 km`부터 광년, 극단적으로 큰 광년 값은 과학 표기법으로 표시한다. 광년 전환 이후에는 표시 정밀도에 따라 숫자가 더 천천히 바뀐다.
- `CosmicClockPage.tsx`와 스타일·천문 데이터는 진입 시 로드한다. 하나의 화면 갱신 루프에서 빛과 네 천체의 거리를 최대 60Hz로 계산하고, 표시값이 바뀐 숫자만 교체한다. React는 초나 기준점이 바뀔 때만 요약을 갱신한다. 구간 데이터는 한 번 정렬한 뒤 경계를 넘을 때만 다시 찾는다. 숨겨진 탭에서는 프레임 요청을 취소하고, 페이지 이탈 시 리스너도 해제한다. 런타임 외부 천문 API나 백그라운드 계산은 없다.
- `초기화`는 복구할 수 없다는 확인창을 열고 `취소`에 먼저 포커스를 둔다. 확인한 시각을 저장한 경우에만 경과 시간과 거리를 0으로 돌리고, 새 출발 시각으로 경로와 카운트다운을 다시 계산한다. 새로고침 없이 기존 루프를 종료하고 새 루프 하나를 시작한다. 쓰기에 실패하면 확인창에 안내하고 기존 출발 시각과 진행 상태를 유지한다. 다른 저장 항목은 변경하지 않는다.

## 계산과 출처

천체 이동 거리 목록에는 천체 이름과 숫자·단위만 보인다. 숫자는 빛의 거리보다 가는 굵기로 표시하고, 줄바꿈이나 말줄임 없이 오른쪽으로 정렬한다. 단위 시작점은 모든 행에서 맞춘다. 다크 테마에서는 `이동 거리` 제목을 옅은 청회색으로 표시하고 양옆에는 같은 길이의 선을 둔다. 경로 아래의 카운트다운은 라벨과 숫자를 여유 있게 띄우고, 숫자 폭을 일정하게 유지한다. 기준계와 계산 방식은 화면 대신 아래에 기록한다.

각 거리는 `경과 초 × 해당 기준계 속도`다. 서로 더할 수 없고, 누적 경로의 길이지 순변위가 아니다. 대표 속도의 장기 불변을 가정한 실제 예측 모델이 아니다. 우주배경복사(CMB)는 물리적으로 정의된 비교 기준계이며 절대 정지 기준이 아니다.

## 기준 거리와 영역

방향을 정하지 않고 지구에서 출발한 빛의 이론적 이동 거리를 **비교용 길이**와 맞춰 본다. 행성은 `화성`, `목성`처럼 이름만 표시한다. 그 외 지표면 고도, 달·태양 거리, 태양 중심 반경과 태양계 근방 거리의 기준은 그대로다.

지구를 제외한 일곱 행성은 저장된 출발 시각의 지구–행성 직선 거리를 근사한다. [NASA JPL 궤도 모델](https://ssd.jpl.nasa.gov/planets/approx_pos.html)로 같은 시각의 두 태양 중심 위치를 구해 벡터 차이의 길이를 사용한다. 지구 중심은 지구–달 질량 중심으로, 역학시(TDB)는 저장된 UTC 시각으로 근사한다. 1800~2050년에는 표 1, 나머지 지원 범위(기원전 3000년~서기 3000년)에는 표 2a·2b를 쓰며, 범위 밖은 J2000.0의 거리로 대체한다. 브라우저에서 진입하거나 초기화할 때 계산하며, 경과 시간과 함께 다시 계산하지 않는다. 새로고침 뒤에도 같은 출발 시각은 같은 기준 거리를 사용한다. 실제 빛의 진로, 도착 시 행성의 위치나 중력 효과는 추적하지 않는다.

`astronomy.ts`의 기준점은 km로 정규화하고 거리순으로 정렬한다. 입자의 위치는 `(빛의 거리 - 구간 시작 거리) / (구간 끝 거리 - 구간 시작 거리)`를 0~1 사이로 제한해 정한다. 거리가 같으면 0으로 나누지 않고 해당 지점을 지났는지로 위치를 정한다. 지점을 넘으면 다음 구간의 왼쪽부터 이어서 표시하며 실제 속도를 과장하지 않는다. 거리 영역은 `시작 ≤ 거리 < 끝`으로 계산하지만 경로에 표시하지 않는다. 마지막 점 이후에도 거리와 시간은 계속 늘어난다. 우주정거장과 정지궤도는 빛이 1초 안에 지나므로 프레임 사이에 건널 수 있다.

지점 유형별 SVG를 재사용한다. 22~24px 심볼은 주로 1.5px 안팎의 획을 쓰며, 이름과 8px 간격을 둔다. 같은 폭의 심볼·이름 묶음이 이름 길이와 관계없이 양끝을 고정한다. 화면의 1px 선만 각 심볼 윤곽까지 줄이고, 입자는 심볼 중심 간의 전체 길이를 기준으로 최대 60Hz에서 CSS `translate`를 갱신한다. 6px 흰 중심과 짧은 네 갈래 빛살은 항상 보이며, 약 34px 보랏빛 광채만 2.6초 주기로 변화한다. 모션 감소 설정에서는 광채 애니메이션만 끄고 위치는 계속 갱신한다.

## 검증

`npm test`에서 최초 방문, 1초·10초·10분·1일·30일·1년·10년·수천 년·수백만 년, 전체 기준점 직전/정확한 경계/직후, 30~180Hz 화면에서의 갱신 빈도, 지연된 프레임 건너뛰기, 동작 중 시계 보정과 숨김·복귀·정리를 검증한다. 일곱 행성의 거리는 [JPL Horizons](https://ssd.jpl.nasa.gov/horizons/)의 2026·2027·2075년 지구 중심 기하학적 거리와 대조하고, 출발일에 따른 순서 변화와 지원 범위 밖 대체값도 검증한다.

브라우저에서 데스크톱·320px/390px 레이아웃, 라이트·다크 테마, 새로고침과 Chromium 프로필 재실행 시 저장 유지, 저장 차단 시 대체 동작을 확인했다. Chromium에서 숨김과 이탈 뒤 시계 갱신이 멈췄고, 초기 반응속도 테스트 진입에는 시계 모듈 요청이 없었다. 390px Firefox·WebKit에서도 거리 갱신과 가로 넘침이 없는 것을 확인했다.

Chrome·Firefox·WebKit에서 초기화의 기본 취소, Escape로 닫기, 저장 실패 시 기존 여정 유지, 확인 후 0부터 재개, 단일 갱신 루프 유지, 새 출발일에 맞는 지점 전환 및 새로고침 후 저장 유지를 확인했다.

레이아웃 개편 전후를 같은 30일 시점의 1440px·390px 화면에서 비교했다. 320px Chromium·Firefox·WebKit에서도 기존 시각 보존, 숫자가 갱신될 때의 정렬, 긴 지점 이름과 마지막 지점 이후의 큰 숫자 표시를 확인했다.

가로 경로와 세로 목록은 1일·30일·1년·10년·100년을 주입해 확인했다. 320px에서도 천체 거리의 숫자는 한 줄이며 단위 시작점이 일치했다. 오르트 구름 진입 직전부터 실행한 화면에서는 카운트다운과 경로가 새로고침 없이 갱신됐다.

Chrome·Firefox·WebKit에서 입자의 구간 중앙 정렬, 경계 통과 시 이름과 카운트다운 전환, 최종 지점, 초기화, 모션 감소를 확인했다. Chrome에서 입자 이동은 초당 약 60회였고, 입자 효과만 분리한 검사에서는 레이아웃 재계산이 없었다.

Chrome에서 14종 심볼의 선 접점과 1440px·390px 렌더링을 확인했다. 280px·320px에서 전체 지점 이름을 대입해도 심볼 중심과 선의 위치가 유지되고 가로 넘침이 없었다.
