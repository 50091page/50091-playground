# 팀 셔플 기능 명세서

## 1. 개요

`팀 섞기`는 두 팀의 같은 행을 독립적으로 좌우 스왑하는 유틸리티다. `#/shuffle`에서 공용 팀 섞기 카드 세 가지와 오버워치 맵 추첨을 제공한다.

- `리그 오브 레전드` 팀 셔플
- `배틀그라운드` 팀 셔플
- `오버워치` 팀 셔플 및 맵 추첨

이 기능은 복잡한 드래프트 도구가 아니라, 빠르게 이름을 입력하고, 필요한 줄만 고정한 뒤, 공정하게 좌우를 섞고, 결과를 바로 복사해 전달하는 데 목적이 있다.

## 3. 화면 구조

공통 헤더는 유지하고 본문 상단의 `게임 선택` 탭에서 한 게임만 표시한다. 하위 탭의 왼쪽은 본문 기준선에 맞추며, 활성 탭은 밝은 글자와 얇은 하단선으로 구분한다. 게임을 바꿔도 URL과 탭 줄의 위치는 유지된다.

| 탭 | 표시되는 카드 |
| --- | --- |
| 리그 오브 레전드 (기본) | 팀 섞기 단일 카드 |
| 배틀그라운드 | 팀 섞기 단일 카드 |
| 오버워치 | 팀 섞기, 맵 랜덤 |

- 단일 카드는 본문 가운데에서 최대 `34rem` 너비로 표시한다.
- 오버워치 두 카드는 `840px` 초과 화면에서 같은 너비의 두 열로 상단을 맞춘다. `840px` 이하에서는 팀 섞기, 맵 랜덤 순서로 세로로 배치한다.
- 좌우 방향키로 탭을 이동하고 `Home`·`End`로 처음·마지막 탭에 이동할 수 있다. 포커스한 탭이 선택된다.
- 비선택 패널은 `hidden`으로 숨기고 마운트 상태는 유지한다. 게임 탭끼리 이동해도 이름, 잠금, 셔플 횟수, 맵 모드·후보, 직전 결과와 진행 중인 애니메이션이 유지된다. 페이지에 다시 진입하면 기본 탭은 리그 오브 레전드다.
- 메인 복귀는 공통 헤더의 `50091` 링크를 사용한다. 팀 카드 내부 구조는 `SwapToolPanel`과 `RowSwapGrid`를 공유한다.

## 5. 데이터 모델

### 5.1 기본 행 데이터

타입: `RowPair`

- `left: string`
- `right: string`

### 5.2 셔플 계산용 행 데이터

타입: `SwapRow`

- `left: string`
- `right: string`
- `locked: boolean`

### 5.3 패널 저장 상태

타입: `SwapToolState`

- `values: RowPair[]`
- `locks: boolean[]`
- `shuffleCount: number`

### 5.4 기본 상태 생성 규칙

`createDefaultSwapToolState(rows)`는 다음 규칙으로 상태를 만든다.

- `values`는 행 수만큼 생성한다
- 각 행의 기본값은 `{ left: "", right: "" }`
- `locks`는 행 수만큼 `false`
- `shuffleCount`는 `0`

## 6. 저장 및 복구

저장은 `useLocalStorage`가 담당한다.

### 6.1 로드 순서

초기 진입 시 상태는 아래 순서로 탐색한다.

1. 현재 저장 키 조회
2. 값이 없으면 레거시 키를 순서대로 조회
3. 유효한 값이 없으면 기본 상태 사용

### 6.2 파싱 및 마이그레이션

`migrateSwapToolState`는 저장된 값을 안전하게 정규화한다.

규칙:

- 저장값이 객체가 아니면 기본 상태 사용
- `values`가 배열이 아니거나 길이가 맞지 않으면 기본 상태 사용
- 각 행의 `left`, `right`가 문자열이 아니면 빈 문자열로 보정
- `locks`가 배열이 아니거나 길이가 맞지 않으면 기본 상태 사용
- 각 lock 값은 `Boolean(lock)`으로 정규화
- 기존 저장값의 `shuffleCount`는 무시하고 항상 `0`으로 리셋

### 6.3 저장 시점

- 상태 변경 후 `200ms` 디바운스로 저장
- 컴포넌트 언마운트 시 최신 상태를 한 번 더 저장

### 6.4 저장 범위

패널별로 다음 정보가 저장된다.

- 좌우 이름 입력값
- 각 행의 잠금 여부

`shuffleCount`는 같은 페이지의 게임 탭을 전환할 때 유지된다. 새로고침하거나 팀 섞기 페이지를 나갔다 다시 열면 `0`으로 시작한다. 맵 추첨은 별도 상태를 저장한다.

## 7. 사용자 인터페이스

### 7.1 패널 구성

각 패널은 다음 구조를 가진다.

- 헤더
  - 게임 아이콘
  - 제목
  - 전체 삭제 버튼
- 본문
  - 행 목록
- 푸터
  - 섞기 버튼
  - 섞기 횟수 초기화 버튼
  - 복사 버튼

### 7.2 행 구성

각 행에는 다음 요소가 있다.

- 역할 또는 티어 라벨
- 잠금 토글 버튼
- 왼쪽 입력칸
- 입력칸 사이의 얇은 구분선 (수동 스왑 버튼 없음)
- 오른쪽 입력칸

리그 오브 레전드 입력만 좌우 블루·레드 색으로 구분한다. 배틀그라운드와 오버워치는 중립 색상의 입력을 사용한다.

### 7.3 상태 표현

- 값이 비어 있으면 게임별 입력 안내 문구를 표시한다
- 잠긴 행은 별도 시각 상태 적용
- 중복 이름은 입력칸 강조
- 중복 이름 입력칸 옆에 경고 아이콘 표시
- 하나라도 중복이 있으면 전역 경고 바 표시

### 7.4 접근성 및 입력 UX

- 각 입력은 `aria-label`을 가진다
- 중복 입력은 `aria-invalid=true`
- 셔플 중에는 입력과 버튼이 비활성화된다
- 빈 입력칸에서 `Backspace`를 누르면 이전 입력칸으로 포커스 이동

## 8. 셔플 규칙

순수 셔플 로직은 `shuffleSwapRows`가 담당한다.

### 8.1 기본 규칙

각 행은 서로 독립적으로 처리된다.

행별 처리 규칙:

1. `locked`가 `true`이면 절대 바꾸지 않는다
2. `allowEmptySwap`이 `false`이고 좌우 중 하나라도 비어 있으면 바꾸지 않는다
3. 그 외에는 `50%` 확률로 좌우를 스왑한다
4. 스왑되지 않는 경우 원래 순서를 유지한다

### 8.2 난수 소스

- 가능하면 `crypto.getRandomValues` 사용
- 브라우저 환경이 지원하지 않으면 `Math.random()` 사용

### 8.3 빈값 처리

기본 설정에서는 `allowEmptySwap = false`다.
즉, 한쪽만 입력된 행은 셔플 대상이 아니다.

## 9. 셔플 애니메이션

애니메이션은 `useShuffleAnimation`이 담당한다.

### 9.1 시작 조건

- 현재 셔플 중이 아닐 때만 시작 가능
- 셔플 중 추가 요청은 무시

### 9.2 동작 방식

- 시작 시 `isShuffling = true`
- 시작 시점의 입력값을 `animatedValues`에 복사
- `40ms` 간격으로 잠기지 않은 행의 미리보기 값을 교대한다. 행마다 간헐적으로 정지하는 타이밍을 달리해 모두 같이 뒤집히지 않도록 한다.
- 입력칸에 흔들림과 빛줄기 효과를 적용한다. 오버워치는 은빛 계열의 셔플 효과를 쓴다.
- 잠긴 행은 애니메이션 중에도 그대로 유지
- `820ms` 후 애니메이션 종료
- 종료 시 `animatedValues`를 제거하고 실제 최종 결과를 상태에 반영
- 사용자가 `섞기`를 누르면 시스템의 모션 감소 설정과 무관하게 팀 셔플 효과를 재생한다. 이 규칙은 오버워치 맵 추첨에 적용하지 않는다.

### 9.3 종료 시 후처리

애니메이션이 끝나면:

- `values`를 최종 셔플 결과로 교체
- `shuffleCount`를 `1` 증가
- `isShuffling = false`

## 10. 이름 중복 감지

중복 감지는 `nameDuplicates` 유틸이 담당한다.

### 10.1 비교 규칙

- 대소문자를 구분하지 않는다
- 앞뒤 공백을 제거한다
- 빈 문자열은 무시한다
- 왼쪽과 오른쪽 컬럼을 같은 이름 집합으로 본다

### 10.2 사용자 표시 규칙

- 중복 이름이 있는 입력칸은 개별 강조
- 입력 목록 아래에 `같은 이름이 여러 칸에 입력되어 있습니다. 셔플 전에 한 번 더 확인하세요.` 경고 표시

이 경고는 시각적 피드백일 뿐, 현재 구현에서는 입력 자체를 막지는 않는다.

## 11. 복사 기능

복사 로직은 `formatRowsForCopy`와 `onCopyRows`가 담당한다.

### 11.1 출력 형식

복사 결과는 줄 단위 텍스트다.

규칙:

- 각 행은 한 줄로 출력
- 좌우 값은 탭 문자(`\t`)로 구분
- 왼쪽 컬럼은 가장 긴 이름 길이에 맞춰 공백 패딩
- 비어 있는 입력은 설정된 fallback 라벨로 대체
- LoL은 맨 위 `블루` / `레드` 헤더를, 오버워치는 각 행 앞에 `[역할명]`을 붙인다. 배틀그라운드는 별도 헤더·역할명 없이 좌우 이름만 출력한다.

오버워치 예시:

```text
[탱커1] PlayerA	PlayerB
[탱커2] 팀 1   	팀 2
```

### 11.2 복사 소스

- 일반 복사는 확정된 `values`를 기준으로 한다. 핸들러는 미리보기 값이 있으면 이를 참조하지만, 화면의 복사 버튼은 셔플 진행 중 비활성화된다.

### 11.3 사용자 메시지

- 성공: `복사가 되었습니다.`
- 실패: `복사에 실패했습니다. 브라우저 권한을 확인해 주세요.`

## 13. 오버워치 맵 추첨

파일: `src/features/overwatch/OverwatchMapTool.tsx`, `src/features/overwatch/overwatchMaps.ts`.

- `모드 선택`, `맵 선택`, `랜덤 결과` 순서로 구성한다. 모드와 맵을 개별 배지로 전환한다. 선택 상태는 체크와 채움으로 구분하며 비선택 배지의 호버만으로 선택된 것처럼 보이지 않게 한다.
- 맵 선택 그룹은 상단 모드 버튼과 같은 순서(쟁탈, 호위, 혼합, 밀기, 플래시포인트, 점령)로 표시한다. 모드를 다시 켜거나 추첨해도 순서를 바꾸지 않는다. 맵 버튼과 그룹 테두리를 낮은 대비로 표시하고, 모드 라벨의 고유 색상과 선택 수는 유지한다.
- 상단 모드 버튼 테두리는 맵 버튼보다 조금 선명하게 유지한다. 그룹 라벨에서는 줄바꿈 없이 모드명을 더 크게 표시하고, 맵 선택 수는 작고 옅게 둔다. 세로 배치에서는 두 줄 사이에 3~4px 간격을 두고, 좁은 카드의 가로 배치는 유지한다.
- 켜진 모드의 맵만 목록에 보인다. 추첨 후보는 **켜진 모드에 속하고 선택된 맵**이다. 모드를 껐다 켜도 그 안에서 개별 선택한 맵은 유지된다. 전체 선택·전체 해제 버튼은 제공하지 않는다.
- 모드는 0개까지 선택할 수 있다. 선택한 모드 또는 맵이 없어 후보가 비면 결과를 바꾸지 않고 안내 토스트를 표시한다.
- `맵 뽑기`는 후보 중 하나를 무작위로 선택한다. 모션 감소 설정이 꺼져 있으면 후보 이름을 `35ms` 간격으로 빠르게 교대하고, `1040ms` 뒤 확정 결과와 누적 횟수를 표시한다. 모션 감소 설정이 켜져 있으면 이름 교대를 생략한다.
- `맵 설정 초기화` 또는 하단 `초기화`는 전 모드·전 맵 선택, 결과 없음, 추첨 횟수 `0`인 기본 상태로 되돌린다.
- 저장 키: `shuffle.overwatch.map.state.v1`. `selectedModes`, `selectedMaps`, `lastDrawnMap`, `drawCount`를 저장한다. 모드 전체 해제는 게임 탭 전환 동안 유지되지만, 페이지를 다시 열거나 새로고침할 때는 현재 마이그레이션 규칙상 전체 모드 선택으로 복구된다. 비어 있는 맵 선택은 복구 시에도 유지된다.

## 14. 테스트 기준

자동 테스트와 브라우저 검증 범위를 구분한다.

### 14.1 셔플 로직 테스트

- 잠긴 행이 유지되는지
- 빈값이 있을 때 스왑 금지 규칙이 맞는지
- 대량 시뮬레이션에서 스왑 비율이 `49% ~ 51%` 범위에 머무는지

### 14.2 상태 헬퍼 테스트

- 기본 상태가 행 수에 맞게 생성되는지
- 저장 상태 마이그레이션이 안전하게 보정되는지
- 복사용 포맷이 탭 구분과 fallback 라벨을 반영하는지

### 14.3 중복 이름 테스트

- 대소문자 무시 비교가 되는지
- 좌우 컬럼을 함께 집계하는지
- 존재하지 않는 이름은 중복으로 표시하지 않는지

### 14.4 맵 추첨과 브라우저 검증

- 자동: 기본 모드·맵 상태, 선택 모드의 전장 표시, 후보 교집합, 저장 상태 마이그레이션.
- 브라우저 수동: 기본 LoL 탭, 키보드 전환, 단일 카드 중앙 정렬, 오버워치 2열과 모바일 적층, 입력·잠금·맵 선택·추첨 결과 유지. 추첨 도중 다른 게임으로 이동한 경우에도 완료된 결과를 확인했다.

## 15. 현재 구현상 제약

- 팀 수를 동적으로 추가하거나 제거하는 기능은 없다
- 입력 데이터의 유효성 검사는 최소 수준이며, 형식 제한보다 빠른 사용성을 우선한다
- 중복 이름은 경고만 하고 입력 차단은 하지 않는다
- undo/redo 기능은 없다
- 멀티유저 동기화나 서버 저장은 없다

---

## 16. 최종 요약

현재 `shuffle` 기능은 다음 특성을 가진다.

- LoL / 배틀그라운드 / 오버워치를 탭으로 분리하고 팀 섞기는 공통 구현을 사용
- 오버워치 맵 추첨과 모드·맵 선택 지원
- 각 행 독립 50% 스왑
- 잠금 행 유지
- 빈값 행 스왑 방지
- 로컬 저장 복구 지원
- 중복 이름 경고 지원
- 결과 복사 지원
- 경량 애니메이션 지원

즉, 이 기능은 `빠른 입력`, `안전한 행 고정`, `가벼운 랜덤 셔플`, `즉시 복사`에 최적화된 클라이언트 전용 팀 섞기 도구다.
